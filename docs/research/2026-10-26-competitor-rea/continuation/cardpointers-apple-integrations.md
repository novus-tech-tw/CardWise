# CardPointers 8.1.4 macOS Apple integrations: configuration options to shared data

This focused offline pass recovers one actual Intents configuration output path. `CPPointersWidgetExtension.IntentHandler` takes a `PointersWidgetOneIntent` options request, obtains shared Core Data parents, maps them into `WidgetOnePointer` options, includes a fixed “Last Viewed” choice, and invokes the completion block with an `INObjectCollection` and a nil error. The WidgetKit executable also contains an options handler that calls the same named shared-persistence and fetch helpers. This does not establish its WidgetKit timeline, rendered entry, or refresh policy.

The targets are the installed **macOS** CardPointers 8.1.4, build 20261019 extensions. This report does not equate them with an iPad build. No extension, intent, permission flow, device, app group directory, or user database was executed or accessed. No Ghidra import was made. All addresses below are unslid virtual addresses in the retained arm64 slice of `CPPointersWidgetExtension`, except the expressly marked CPWidget comparison. Raw LLVM nearest-symbol comments such as `plcrash…+offset` and `_write+offset` are not treated as function identities.

**CPAI-02 — Shared data is bound to an App Group SQLite store, with an explicit failure boundary.** The shared accessor uses `swift_once` initialization `0x10018d4bc`, which calls the persistence constructor `0x10018e7c4` with normal-mode argument zero and stores the object in its shared global. The constructor creates an `NSPersistentContainer` with name `coredata`. Its selected URL initializer `0x10018d57c` passes `group.getcardpointers.app` and `cardpointers` to exported `Foundation.URL.storeURL(for:databaseName:)` at `0x10018c230` (`0x10018d5e8` call).

That function obtains `NSFileManager.defaultManager`, calls `containerURLForSecurityApplicationGroupIdentifier:` at `0x10018c2ec`, and on success appends the supplied database name plus `.sqlite` at `0x10018c370`. On a missing container URL, its branch at `0x10018c30c` reaches the literal “Shared file container could not be created.” and Swift `_assertionFailure → Never` at `0x10018c3f4`, followed by a trap. This is not a graceful storage fallback. The constructor binds the URL to an `NSPersistentStoreDescription`, sets store descriptions, and calls wrapper `0x1001a5b50` at `0x10018eebc`; that wrapper reaches `loadPersistentStoresWithCompletionHandler:` at `0x1001a5ee4`. Observation: the shared data setup is concrete and can initialize persistent storage. Inference: the options candidates are read through that shared App Group Core Data configuration. Limit: this pass did not inspect the live store, migrate it, or expand store-load retry/error callbacks. “Read-only investigation” must not be mistaken for a claim that this shipped initializer itself never writes.
